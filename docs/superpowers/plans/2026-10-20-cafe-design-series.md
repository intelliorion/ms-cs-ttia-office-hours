# Creators' Café design series: tool picker, brainstorm, design.md, plan and kits — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From an idea's details in the left panel, the operator picks one approved tool per feature (with the AI's reasons and pathway flags), runs a one-question-at-a-time design brainstorm with the embedded brainstorming skill, gets `design.md` filled in live and closed with a Café check, and on approval gets `plan.md` plus a starter kit per tool, with custom-app builds handed to a coding agent.

**Architecture:** Server-side `src/design/` owns the files per idea (`approach.md`, `design.yaml` state, `design.md`, `plan.md`, `kit/<tool>/`), the Café check (code rules), and three schema-checked AI tasks (`toolPickTask`, `designStepTask`, `designPlanTask`) through the existing connector; the two superpowers skills are embedded as text under `cafe-app/skills/` (MIT, notice kept) and sent as guidance inside the prompts with the Café rules on top. The UI adds two sections to the idea details view in the left panel. The universe gains Capability→Tool links from picks (form-grade, source `approach.md`).

**Tech Stack:** as before. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-creators-cafe-app-design.md` §6 (binding), §4 (steps s3c–s3f are background log; stage moves only on Yes), §9 (BUILT_WITH/NEEDS links from picks), §10–§11 (AI rules, data). Tools and pathways: `skills/ms-cs-ttia-creators-cafe/SKILL.md` Part 3 (Citizen-Led / Assisted Citizen: Copilot Studio · Power Apps · Dataiku · UiPath, plus Microsoft Copilot with no build; a custom app is TTIA-Led → needs the CSIC Repository).

2. **"I don't know" on the first question with no E2 ever sent.** Expected: an E2 draft containing that question appears in the Outbox; the design step stays open. *Task 3.*
3. **Approving a design whose Café check has a CSIC flag.** Expected: approval allowed, but `design.md` and the notice say the idea has a CSIC feature, and a stage suggestion "Close as Routed to CSIC?" appears (never automatic). *Task 3.*
4. **Re-running the tool picker after picks were saved.** Expected: existing picks kept unless the operator changes them; graph links updated, never duplicated. *Task 2.*
5. **plan.md for a custom-app pick.** Expected: the kit contains a copy-ready "Build with Claude Code / Copilot" instruction and a CSIC note (custom app is TTIA-Led), no code generated by the app itself. *Task 4.*

### Task 2: Tool picker (server + AI)
**Files:** `src/design/tools.ts`, `src/ai/tasks.ts` (+`toolPickTask`, fake reply), `src/server/api.ts`, tests `tests/design-tools.test.ts`.
**Interfaces:**
- `PATHWAYS`: `{ 'Microsoft Copilot': 'Citizen-Led (no build)', 'Copilot Studio': 'Citizen-Led', 'Power Apps': 'Citizen-Led', 'Dataiku': 'Citizen-Led', 'UiPath': 'Citizen-Led', 'custom app': 'TTIA-Led (CSIC Repository)' }` plus the Assisted Citizen note when a builder is not yet named.
- `toolPickTask`: input `{ idea: IdeaText, support[], existingFeatures? }` → `{ features: { name ≤60, what ≤160, tool: enum APPROVED_TOOLS, reason ≤160, flags: ('needs-live-system'|'personal-data'|'custom-app'|'reuse-existing'|'no-build')[] }[] (1–6) }`; prompt includes the approved tools with one line each on when to use them (from the Café skill Part 3) and the Café rules.
- `POST /api/ideas/:id/tools/suggest` → runs the task, returns features as suggestions (nothing saved). `POST /api/ideas/:id/tools { features }` → validates tools ∈ APPROVED_TOOLS, saves `design.yaml` (status 'picking'→'designing' when ≥1 pick), writes `approach.md`, ticks background step s3e (source approach.md), and upserts graph links: `idea NEEDS capability:<feature>` and `capability:<feature> BUILT_WITH tool:<tool>` as **form-grade** links (confidence 1, source `form:<id>:approach.md`) via `buildGraph`'s existing `tools` reading (extend `Idea.tools?: Record<feature, tool>` or read approach from design.yaml in `build.ts`) — no AI links, no duplicates on re-save (Review Focus 4). `GET /api/ideas/:id/design` returns the state + rendered design.md.
**Tests:** schema rejects an unlisted tool; save → approach.md + s3e tick + graph links present once after two saves; changing a pick replaces the BUILT_WITH link; fake suggest returns 3 features incl. one `custom-app` flag.

### Task 3: Design brainstorm (server + AI)
**Files:** `src/design/brainstorm.ts`, `src/ai/tasks.ts` (+`designStepTask`, fake), `src/server/api.ts`, tests `tests/design-brainstorm.test.ts`.
**Interfaces:**
- `designStepTask`: input `{ idea, features, stepsSoFar: {question, answer}[], guidance: skillGuidance('brainstorming') }` → `{ done: boolean; question?: ≤200; why?: ≤160; suggested?: string[] (2–4, ≤120 each); summary?: ≤600 (only when done) }`. Prompt: the brainstorming skill's "one question at a time, multiple choice when possible, purpose/constraints/success criteria" guidance + Café rules (never ask for value/ROI; never ask for personal data; aim for: the one thing the PoC must show, the smallest synthetic input, who uses it, what it replaces, the builder) + "reply with one JSON object".
- `POST /api/ideas/:id/design/step` → next question (or done+summary) appended to state; `POST /api/ideas/:id/design/answer { n, answer | 'idk' | suggestedIndex }` → records the answer; `'idk'` drafts an E2 with the question text replacing `[QUESTION 1…]` (reuse `draftEmail` + `updateDraft`), stores `askedTeam.emailKey`, keeps the step open; when an Inbox reply later records an answer whose question matches (reuse `sameQuestion`), fill the step with `source:'e2'` (hook in `src/inbox/actions.ts` record_answers → `fillDesignAnswer`). Every state change re-renders `design.md` (live) and runs `cafeCheck`.
- `POST /api/ideas/:id/design/approve` → requires `done`; stores `approvedAt`, ticks s3f (source design.md), returns `{ suggest?: { closeAs:'csic', label:'Close it as Routed to CSIC?' } }` when `cafeCheck.csicFlags.length` (Review Focus 3), never moves the stage itself. Also ticks s3c/s3d when the answers cover "the one thing it must show" / "smallest input" (match by step tags the AI returns: add optional `tag: 'must-show'|'smallest-input'|'users'|'replaces'|'builder'|null` to the step schema).
**Tests:** step → answer → step loop with the fake; `idk` → E2 draft contains the question, step open; a later Inbox-recorded answer fills it; approve before done → 400; approve with a csic flag → suggestion; design.md updates after each answer and ends with the Café check; injection text in an answer never changes stage/anything outside the step.

### Task 4: plan.md and starter kits (server + AI)
**Files:** `src/design/kits.ts`, `src/ai/tasks.ts` (+`designPlanTask`, fake), `src/server/api.ts`, tests `tests/design-kits.test.ts`.
**Interfaces:**
- `designPlanTask`: input `{ idea, design summary, features+tools, guidance: skillGuidance('writing-plans') }` → `{ tasks: { title ≤80, detail ≤300, tool: enum, done_when ≤160 }[] (3–12), risks: string[] (≤5, ≤160) }`. `renderPlanMd` writes plan.md (header, the one thing to show, tasks per tool, risks, Café check copied from design.md).
- Kits are **code templates**, one folder per picked tool under `ideas/<id>/kit/<slug>/`: Copilot Studio (`README.md` + `topics.md` outline from features), Power Apps (`screens.md`), Dataiku (`flow.md` with synthetic-data step first), UiPath (`process.md`), Microsoft Copilot (`prompts.md`: no build), custom app (`README.md` with a CSIC note + `BUILD-WITH-AGENT.md` containing a copy-ready instruction for Claude Code / Copilot that points at design.md and plan.md and says "write only inside this kit folder"). The app never generates application code itself (Review Focus 5).
- `POST /api/ideas/:id/plan` → requires approved design; runs the task; writes plan.md + kits; returns `{ files: string[] }`; background tick none (s3f already). Idempotent: re-running overwrites plan.md and kit READMEs but never deletes operator-added files in `kit/`.
**Tests:** plan.md contents; kits per tool; custom app kit has the agent instruction and the CSIC note; re-run keeps an operator file; unapproved → 400.
